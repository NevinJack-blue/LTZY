# LTZY · AI 模型网关产品与界面设计方案

> v0.1 · 待评审。LTZY 是暂用项目名。本文件是原创方案，不是已上线功能、已验证市场结论、定价公告或服务承诺。本文只定产品和设计，不锁定框架，不修改现有页面。

## 01 / 产品定位：让每次模型调用都说得清

**面向已有 LLM 调用量的小型产品和研发团队，提供一个可控制预算、可核对账单、可追查故障的统一模型 API。** 首页文案建议：**「一个 API 接多家模型。每一次调用，都有据可查。」**

首批用户优先找正在同时维护两个模型上游的 2–10 人团队：开发者负责接入与排错，项目负责人负责预算，平台运营负责上游与异常。暂不以单纯追求低价的散客、个人订阅共享或企业私有化为首版目标。

| 待验证的痛点 | LTZY 的设计回应 | 如何验证而不是自说自话 |
|---|---|---|
| 账单只有总金额，无法解释费用波动 | 逐请求小票：输入/输出、计价版本、状态、待核账标记；能按项目导出 | 让用户拿最近一张账单找出一笔异常成本并解释原因 |
| 请求变慢或失败后，不知道是哪层出问题 | 路由轨迹串起鉴权、候选筛选、尝试、流首字节与结算；提供可复制请求 ID | 给一条模拟 429 和一次流中断，看用户能否区分下一步 |
| 同名模型的能力、实付和上游差异不透明 | 模型详情区分公开模型 ID、实际提供方、已验证能力、价格口径与更新时间 | 让用户找一个支持工具调用且在预算内的模型；未验证必须显式显示 |
| 首次接入要在文档、Key 和账单间来回跳 | 一个接入向导串起项目、发 Key、复制示例、成功回执，回执直达小票 | 计时从进入控制台到发送首个成功请求，记录卡住的步骤 |

**验证顺序：**先约 5–8 个目标团队，收集脱敏账单/真实失败案例；做下述三屏可点击原型，再访谈和走查。内测目标建议：受测开发者能独立完成首调，首调中位用时 ≤ 5 分钟；从请求 ID 找到费用与故障归属中位 ≤ 60 秒。目标不是现有实绩。上线后分项目追踪首次成功请求率、故障自助定位率、账单待核对占比，并明确统计窗口与样本量。

视觉曾比较三种气质：**精密仪表**擅长排障，但整站暗色会压低阅读舒适度；**编辑式目录**适合讲品牌，但不够支撑高频运维；**纸感账本 × 信号控制台**能用同一套视觉语言解释钱和请求，作为本案唯一推荐方向。参考只用于对照，并未导入第三方设计系统。

## 03 / 原创视觉：浅纸底账本，一条信号轨迹

- **用户与场景：**桌面 1440 px 为控制台设计基准；390 px 优先支持浏览模型、复制示例、查看单次请求和撤销 Key。复杂跨列运营表在窄屏切成列表与详情。
- **主角与动作：**访客首屏的主角是一次调用轨迹，主动作「开始接入」；已登录首屏的主角是真实请求，主动作视状态为「创建 API Key」或「查看请求」。
- **构图：**官网用通栏上下堆叠：短标题 → 单个通栏 SVG 轨迹 → 证据与模型入口。控制台首屏直接给项目切换和内容，不放营销横幅；运营台先放异常队列。
- **配色来源：**暖白像账单纸，墨色像印刷数字，钴蓝专门表示选中路径或可执行动作。价格、状态、路由都不靠颜色单独表达。
- **排版：**中文用系统无衬线（苹方 / 微软雅黑 / Noto Sans CJK 兜底），拉丁用系统无衬线，ID/用量数字用系统等宽并启用等宽数字。标题利落，账单数字列右对齐。
- **状态：**营销演示须手动播放，控制台根据数据进入空、成功、异常、待结算状态；不做滚动劫持、全站背景动画或数字反复跳动。

| Token | 建议值 | 用途 |
|---|---|---|
| canvas / surface | #F7F6F1 / #FFFFFF | 页面 / 信息与浮层 |
| text / muted | #17233A / #516078 | 主文字 / 说明、注释 |
| line / focus | #DCE1EA / #2455CC | 分隔线 / 交互焦点 |
| accent / accent-soft | #2455CC / #EAF0FF | 主按钮 / 选中底色；按钮白字 |
| success / warning / danger | #176A52 / #875100 / #AA2836 | 状态文字，配图标和标签 |
| 字号层级 | 官网标题 56/64，移动 36/44；控制台页标题 28/36；正文 14/22 | px，中文实际换行以原型验收 |
| 网格和圆角 | 4/8/12/16/24/32/48/64 间距；8 控件、12 浮层 | 宽屏官网最大 1200；控制台桌面侧栏 232、详情抽屉 520 左右 |

组件优先用留白、字重、对齐做分组；仅表头、价格、交互边界用线。焦点环不可被裁掉；正文对比 ≥ 4.5:1，关键非文字控件 ≥ 3:1，需在真实渲染中实测，不视为已通过。

## 04 / 页面结构与首版顺序

| 区域 | 页面 | 上屏与主要动作 | 优先级 |
|---|---|---|---|
| 官网 | 首页 | 价值句、开始接入、通栏交互轨迹；下方放计价示例和隐私说明 | P0 |
| 官网 | 模型目录与详情 | 首行搜索及能力筛选；列表显示模型 ID、按单位计价、能力、可用性更新时间；动作「复制模型 ID」 | P0 |
| 官网 | 文档、状态 | 文档首屏提供可复制的 Curl/Python；状态页写服务范围、事件历史与观测口径 | P0；首版用简版 |
| 控制台 | 接入 / 项目总览 | 无数据先给接入任务；有数据则给近期请求、预算使用和最新异常，链接到同筛选结果 | P0 |
| 控制台 | API Keys / 预算 |创建、限权、撤销；项目硬预算与告警阈值；查看生效时间和操作者 | P0 |
| 控制台 | 请求日志 | 项目、时间、模型、状态、请求 ID 筛选；点一行打开可深链的请求轨迹 | P0 |
| 控制台 | 用量与账单 | 用量按项目/模型拆开，展示已结算、待核对、调整；支持明细导出，不用余额代替账单 | P0 |
| 运营台 | 上游、路由、对账 | 异常队列 → 查看影响范围；有版本地启停渠道、预览策略、对账修正，留审计 | P0 最小可用 |
| 后续 | 模型试验场 / 策略编辑器 / 商业收款 | 同提示对比、费用上限策略、支付退款等分别验证；未上线不显示假入口 | P1+ |

### 三个应该优先画出来的高保真页面

**A. 官网首页 · 先讲为什么值得换。** 顶栏为品牌、模型、文档、状态、控制台；通栏大标题下放「开始接入」与「浏览模型」。下方只给一张轨迹：**调用 → 规则 → 结果 → 费用**。演示「正常请求 / 上游 429」两种状态，旁边标「示例数据」；点开费用直接显示取价快照。页脚写价格口径、数据政策与联系入口，不用虚构客户 Logo 或可用率。

**B. 模型目录 · 先帮用户选。** 筛选顶部粘住，带结果数、清空筛选按钮，可用 URL 分享。列表只保留影响决策的列：模型名/ID、能力、输入/输出价、健康更新时间。详情显示已验证/不支持/待验证、上下文规格、参考代码和价格更新来源。首版只列上架且验证过基本调用的合法上游模型。移动端保留模型 ID 和价格，不把它们藏进横向滚动。

**C. 请求详情 · 一屏说明为什么。** 第一行：请求 ID、时间、结果、复制按钮。第二行：请求模型、实际模型/可披露上游、延迟、金额。下方两块：按顺序的路由轨迹与费用小票。每步显示发生原因、尝试编号、耗时和可执行建议；等待确认的用量显示「待核对」，不能填 0 冒充已结算。空详情、无权限、请求已过保留期须用不同提示；关闭抽屉回到原列表与焦点。

**完整首调链路：** 建项目 → 创建最小权限 Key（明文只显示一次）→ 选模型并复制带占位符的示例 → 从本地发起请求 → 控制台看到真实回执 → 展开请求详情与用量。示例不把真实 Key 放进页面地址或日志。无调用时说明等待什么，不显示虚假图表；复制失败给可手选文字。

### 三屏的首屏线框

```text
官网（通栏）          模型目录（先搜索）        请求详情（桌面详情抽屉）
[品牌 · 导航 · 控制台]  [搜索 · 能力 · 筛选]       [结果 · 请求 ID · 复制]
[价值句 · 开始接入]    [模型 / 能力 / 输入输出价]  [模型 / 耗时 / 金额]
[示例轨迹 ────▶ 回执]   [模型 / 能力 / 输入输出价]  [尝试 1 → 尝试 2 → 结果]
[计价示例 · 隐私说明]  [详情：价格口径 · 代码]    [费用小票 · 计价版本]
```

## 05 / 体验签名：请求轨迹与费用小票

### 请求轨迹不是装饰

顺序为「鉴权与预算 → 模型能力校验 → 选择授权渠道 → 调用与响应 → 计量/结算」。例：用户请求模型 A；首选上游在返回任何内容前报 429；策略允许、有预算余量、同一模型的备用上游才获一次回退机会。轨迹显示为何选备用，以及最终落到哪个模型。**流已经输出后不悄悄重放**；明确标记中断和账务状态。用户只看到允许披露的信息，运营可在授权下查详细渠道；任何角色都不应看到无关凭据。

### 账单数字都能追溯

每条小票至少包括币种、计费单位、输入/输出（支持时另列缓存）、定价版本、请求 ID、金额和时间。定价示例必须标「示例」。费用估算和实扣分开；请求结束但用量未到时显示待核对，处理方式写进计费说明。客户账与上游尝试成本分账：同一请求即使网关内部发生多次尝试，也不得重复生成客户扣费。通过固定精度、不可变价格快照、幂等入账及调整流水实现可复核；先定义异常/中断收费政策，再做收款。

## 06 / 页面动画规范

| 场景 | 触发与时序 | 表达的含义 | 降低动态效果时 |
|---|---|---|---|
| 官网轨迹 | 点击「播放示例」后，SVG 依序点亮节点与线段，总长约 850 ms；可重播，不自动循环 | 看清网关做了哪几件事；出现回退时线旁写原因 | 直接显示完整五步与解释，无位移 |
| 打开请求详情 | 160–200 ms，抽屉小幅移动与淡入；关闭约 140 ms | 保留它与原请求列表的关系 | 立即出现，保持焦点转移与归还 |
| 模型切筛选 | 约 120 ms 更新选中态；加载期间保留布局，标记旧结果正在刷新 | 筛选生效，不误把旧数据当新结果 | 更新选中态和文字，不做过渡 |
| 路由回退 | 真实状态到达后用一次短色变标明尝试编号；不画虚构流量 | 不是模型偷偷换了，而是同模型尝试了另一上游 | 改图标与文字即可 |
| 复制、保存 | 约 100 ms 按钮反馈，显示「已复制」或具体错误；保存中防重复提交 | 明确动作成功与否 | 文案与无障碍通知保留 |
| 账单及长表 | 不做总金额滚动，不弹跳重排；新数据可用提示条提示后手动载入 | 数字是证据，不是装饰 | 一致 |

工程默认只动画化 transform / opacity；SVG 轨迹例外但须测低端移动设备。遵守 prefers-reduced-motion；演示对键盘可用，不能只靠悬停；即时状态用适量的无障碍通知，避免每个流式 token 都播报。无声、无全屏动效、无滚动锁定；功能不依赖动画播完才可操作。

## 07 / 工程首版与上线门槛

**推荐路径：**完整自研用户体验，先做独立网关的最小闭环；若为快速测试选择接现有网关，必须先验证请求追踪、计量、错误映射、许可和可维护性，不让目标界面依赖已有网关后台。建议模块：用户与项目、模型与授权上游适配、路由、SSE 流式转发、计量与账务、审计。首版实现 OpenAI 兼容的模型列表、聊天（普通 + SSE）；不宣称支持未完成验证的 Tools、Responses、图像等。先接一个授权上游跑闭环；两条测通的授权线路具备同模型能力后才对外开放回退。

| 阶段 | 最小交付 | 通过条件 |
|---|---|---|
| 原型 | 首页、模型目录、请求详情；补一条建 Key 到首调的可点击流程 | 桌面与窄屏走查，明确示例数据；能解释一次成功和一次故障；确认视觉再做工程 |
| 封闭内测 | 项目/Key、真实请求、日志、预算、计量和运营告警 | 普通与流式端到端，401/429/超时/流中断覆盖；压力下并发扣费不突破设计的预算保护（预留最大允许成本、请求结束结算/释放）；无跨租户读取 |
| 准备运营 | 多上游核验、价格版本、账单对账、故障手册、必要时接入支付 | 获得商业授权；明确报错/退款/中断计费、隐私政策与数据保留；可撤销 Key、可回滚路由版本。支付与财税合规未完成前，不开放真实充值 |

隐私默认仅记必要元数据，不记录提示词或生成正文；对供应商处理、可见地区与保留期限另行披露。上游密钥不得进浏览器、文档或公开代码；运营侧最小权限并记录审计。首调成功率按「新项目发起过请求」与「所有新项目」分别看，费用与健康数据有时间范围和样本量，样本不足不能显示为健康。

## 08 / 这轮请确认的决策

1. **首批客户：**推荐已有调用量的小团队，而不是以低价吸引大量个人用户。
2. **首版产品承诺：**推荐优先做「请求可追踪、费用能对账」，不以模型数量或最低价为卖点。
3. **运营形态：**推荐先封闭内测，用测试或管理授予额度验证账务；面向公众收费另立评审。
4. **视觉方向：**推荐确认「纸感账本 × 信号控制台」，看完三屏高保真再定组件规范与技术实现。
