# LTZY 本地网关运行手册

服务为单机单管理员设计。默认只使用 local/echo。若只想验收权限、预算和账单，不需要任何外部账户。

## 自有上游

停止原服务，在同一终端给 LTZY_UPSTREAMS 设置 JSON 数组；每项是一个支持文本 Chat Completions 的 HTTPS 渠道。凭据通过 api_key_env 引用的环境变量提供，从凭据管理器注入，不要把真实密钥粘入源码、配置示例或共享终端记录。配置在启动时加载。以下是结构示例，域名、模型名和费率都必须换成供应商实际约定的值：

~~~json
[{"id":"primary","model":"team/chat","upstream_model":"provider-model-id","base_url":"https://provider.example/v1","api_key_env":"PROVIDER_KEY","input_price":0.5,"output_price":1.5,"context":8192,"price_version":"contract-v1"}]
~~~

模型 ID 相同的渠道按数组顺序尝试；每条线路都应确认映射到同一模型。缺少凭据不应当作可用线路。未设置 LTZY_UPSTREAMS 才启用本地测试；配置了真实线路时不会退回模拟回复。公开目录和服务状态来自实例配置及累计请求观测，并非外部健康探针。

## 首次验证与对账

1. 在工作台创建聊天权限的 Key。开发者文档生成当前实例的 URL、模型名和请求示例；先执行一个短的非流式调用，再验证 SSE。首次使用商业上游会产生对方约定的费用。
2. 对照响应中的请求 ID、供应商实际用量及工作台小票。路由按收到的可重试 HTTP 拒绝响应（429、502、503、504）尝试同模型备用；网络断开等结果不明的情况不盲目重发。输出开始后绝不切换线路重放。
3. 价格按每百万输入/输出 token 的美元费率，计算后按笔向上取整至微美元；预算是项目累计硬上限，不是自动重置的月度额度。请求先预留后结算；计量不可靠或进程异常退出的记录保留待核对和预留。核对依据是提供方用量，不是人工猜测；操作保存调整依据。此账本不执行支付，也不替代提供方的正式发票。
4. 撤销该 Key，再尝试列模型，预期返回 401。重新签发而不是重用已撤销 Key。

## 数据与备份

数据仅存于指定目录（默认 .ltzy），不在 Web 静态文件目录内。管理员密码文件与数据库都是敏感材料；Windows 请将目录放在仅运行账户可访问的位置并检查 NTFS 权限。系统不记录请求正文或上游凭据到请求小票。SQLite 数据包含项目 Key 摘要、会话摘要、用量、请求 ID 和线路信息，仍须保护。

停止服务后备份整个私有数据目录；恢复时停服并用备份目录启动，不要让两个服务共用同一个目录。遗失管理员密码时，在确保本机账户可信且已停服的前提下，将密码文件移出数据目录再启动以重新生成；重置密码不等同于撤销所有已有会话或 API Keys，应另外处理。工作台显示最近 200 条请求，待核对队列和 CSV 不受该窗口限制。

## 验收范围

单元与本机集成测试覆盖登录、权限、重启恢复、并发预算、线路保护、HTTPS 测试上游、流式输出与中断、对账和凭据撤销。浏览器验证使用隔离数据库，既没有产生真实供应商费用，也没有验证任何特定商业模型。上线前还需独立部署安全评估、供应商联调及备份恢复演练。
