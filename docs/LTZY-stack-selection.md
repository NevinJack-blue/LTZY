# LTZY 技术栈选型 · ADR-001

状态：建议采用，待最小工程验证；未初始化工程、未安装依赖。产品目标参见 [产品设计方案](./LTZY-product-design.md)。

## 本地基线

- 仓库尚无 Node/Go/Python 依赖清单、锁文件、构建配置、后端或 CI。根目录 [HTML 演示](../index.html) 是独立的鹈鹕动画，不是 LTZY 前端，不改动、不纳入新构建。
- 本机 Windows amd64。命令实测：Node.js v24.19.0、npm 11.17.0、pnpm 12.9.1、Corepack 0.35.0、Go 1.27.1、Python 3.14.7。它们是探测结果，不是项目最低版本或生产镜像版本。
- PATH 未发现 Docker、psql、redis-cli，Docker Desktop 默认位置也未发现。尚未验证可用的 PostgreSQL 实例或容器环境；不假定数据库服务已就绪。

## 选型结论

| 层 | 推荐 | LTZY 的理由 |
|---|---|---|
| 用户界面 | Next.js App Router + React + TypeScript，pnpm | 同一 Web 应用容纳官网、模型目录、文档与控制台；公开页可预渲染或服务端渲染；交互组件按需上客户端。 |
| 视觉与动效 | CSS Variables + CSS Modules + 内嵌 SVG | 为原创配色、账单布局、请求轨迹做专用组件；CSS 负责状态过渡和 reduced-motion；复杂动效库暂缓，优先保留无障碍焦点和可读性。 |
| API 服务 | Go + 标准库 net/http | 用一个模块化单体承载鉴权、适配、路由、用量与审计；网关直接控制 SSE 刷新、连接取消、超时与重试边界，不把推理流经由 Next.js 二次转发。 |
| 数据层 | PostgreSQL + pgx；版本化 SQL 迁移，类型生成按需要加入 | 请求、价格快照、预算预留、结算与审计可在同一数据库建立清晰事务边界。金额使用定标整数或精确 decimal，不使用浮点。 |
| 测试与观测 | Go testing/httptest；Playwright；结构化日志与基本指标 | 用模拟上游做稳定回归；从服务端日志按请求 ID 串起尝试和结算，默认不记录正文或凭据。 |
| 部署 | 一个仓库，Web 和 API 两个进程，独立 PostgreSQL | 本地原生运行 Next.js 与 Go；部署时经反向代理分流，先验证 SSE 路径无缓冲。应用镜像和 Compose 留到确认容器环境后。 |

建议目录为 apps/web、services/gateway、docs、以及按需增加的 deploy；仅为规划，尚未创建。控制台经同源管理 API 调 Go；对外的 /v1 路径直接代理至 Go，平台 API Key 与浏览器会话分别鉴权。版本在初始化时从受支持稳定版中选取，在清单、锁文件与 CI 中固化；不能用本机上能执行代替正式兼容验证。

## 取舍

- **全 TypeScript（Next.js + 独立 Node/Fastify）：**少一种语言，初期更省维护，也能做 SSE。如果团队没有 Go 维护能力，优先复评此路线，而不是强推双栈。当前考虑到网关将独立演进、希望原生掌控长连接，先验证 Go；没有做吞吐对比，不宣称更快。
- **Vite + React SPA：**控制台开发简单；若确定公开目录和文档无需 SSR/预渲染，可改用它减少一层 Node 运行时。当前公开页与控制台并重，先选 Next.js。
- **现有 New API 后端 + 原创前端：**能更快拿到多上游支持，但需先核实许可证、能否完整提供路由轨迹和价格快照、升级是否会影响接口。当前首版只接一个上游，优先自研薄网关验证差异化，不复刻全量功能。
- **SQLite、Redis 与微服务：**SQLite 不作为首版正式账务存储，避免原型与 PostgreSQL 在并发事务上行为不一致；Redis 后置到跨实例限流/缓存有明确需要时，不能作为账务真相源。不先引入 MQ、Kubernetes 或独立计费服务。

## 第一条可验证的工程切片

1. 先建立最小 Web 和 Go 骨架，用模拟上游跑通模型列表与普通、SSE 聊天；不需要真实 Key、数据库或 Docker。确认流式首包不是整包缓冲、客户端断开会取消上游、流开始后不透明重试。
2. 接好开发 PostgreSQL（本地原生，或受控的专用开发实例），做一个项目、一个模型和一条可查询请求：价格快照 → 预算预留 → 尝试 → 结算或待核对。短事务预留/结算，不把数据库事务挂在整个流上；用唯一键避免同一请求重复扣费，并测试并发预留、失联恢复和租户隔离。
3. 上述两段稳定后再接一个授权真实上游。界面用一条成功记录和一条失败记录验证「请求轨迹 + 费用小票」。真实费用、不确定用量与模拟金额必须区分。多节点、真实充值和高级路由不在第一切片。

选型通过条件：Windows 开发环境与 Linux CI 可以重复构建；反向代理后的 SSE 正常逐段到达且能取消；PostgreSQL 并发结算测试通过；桌面与窄屏均能从请求 ID 查到状态和费用。以上尚未实施或实测。
